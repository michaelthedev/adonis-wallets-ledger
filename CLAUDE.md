# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

AdonisJS 7 (ESM, TypeScript) JSON API implementing multi-currency user wallets backed by a double-entry, append-only ledger. Lucid ORM on MySQL, token auth (`@adonisjs/auth` access tokens), VineJS validation, Japa tests.

**Working mode:** the author hand-writes the code (a learning project; background is Laravel/PHP). Claude Code's role is review and progress checkpointing — don't implement features unless explicitly asked.

**Planning docs live in `.keep/` (gitignored):** `ledger-wallet-plan.md` (the 7-phase build plan), `ledger-status-report.md` (current checklist of done/open items, ledger rules, reading list), and per-topic reports like `assert-balanced-report.md`. When asked for a status update, verify each open item against the code and test/typecheck/lint output, then update `ledger-status-report.md`.

## Commands

```bash
npm run dev                 # node ace serve --hmr
npm run build               # node ace build (output in build/)
npm test                    # all suites (unit + functional)
npm run lint                # eslint
npm run typecheck           # tsc --noEmit
npm run format              # prettier

node ace test functional                              # one suite
node ace test --files=tests/functional/wallets/transfer.spec.ts
node ace test --tests="fails on self transfer"        # one test by title

node ace migration:run      # also regenerates database/schema.ts
node ace ledger:verify      # ledger integrity checks; exits 1 on any failure
```

Tests need a running MySQL with the `adonis_wallets_test` database (see `.env.test`, which overrides `.env`). The test bootstrap runs migrations; each functional test group wraps tests in a global transaction (`testUtils.db().wrapInGlobalTransaction()`).

## Architecture

**Ledger model (the core invariant).** Balances are never stored. A wallet's balance is `SUM(credit) - SUM(debit)` over its `ledger_entries` (`Wallet.balance()`, `WalletService.listWithBalance()`). Amounts are unsigned integers (`bigInteger`, validators enforce `withoutDecimals`) — treat them as minor units.
- `LedgerEntry` is append-only: model hooks throw on update/delete. Corrections must be new entries, not edits.
- Every `Transaction` groups ledger entries. Transfers must net to zero per currency (`TransferService.assertBalanced`); deposits/withdrawals are single-sided and are excluded from that check.
- Transactions are created `pending`, entries written, then flipped to `completed` with `completedAt` — all inside one `db.transaction`. `Transaction.uid` is a UUID assigned in `beforeCreate`.
- `commands/ledger_verify.ts` codifies the invariants (C1 net-zero, C2 no negative balances, C3 entry currency = wallet currency, C4 completed txns have entries, C5 no stale pending). Keep it in sync when adding transaction types. Its SQL is MySQL-specific.

**Concurrency.** Money-moving code runs inside `db.transaction` and locks the sender wallet row with `.forUpdate()` before reading the balance. Pass the `trx` client through every query (`{ client: trx }`) — services accept an optional `trx` for this. `WalletService.findOrCreate` handles the `(user_id, currency)` unique-constraint race by catching `ER_DUP_ENTRY` (MySQL error code).

**Layering.**
- `start/routes.ts`: everything under `/api/v1`; routes reference controllers via the generated `controllers` object from `#generated/controllers` (`.adonisjs/server/`, regenerated by the dev server/assembler hooks — don't hand-edit). Route names (e.g. `wallets.transfer`) are used by tests via `client.visit(...)` with types from the Tuyau-generated registry in `.adonisjs/client/`.
- Controllers extend `ApiController`, which provides `getUser()` and `response(...)` producing the uniform envelope `{ success, message, data }` (success = status < 400). `data` goes through `ctx.serialize` (added in `providers/api_provider.ts`).
- Business logic lives in `app/services/` and is injected with `@inject()` (constructor or controller-method injection).
- Domain errors are `Exception` subclasses in `app/exceptions/` with their own `handle()` returning the same envelope.
- Output shaping uses transformers in `app/transformers/`.
- Registration creates default wallets (`DEFAULT_CURRENCIES` in `app/constants/currencies.ts`) in the same DB transaction as the user. Transfers auto-create the receiver's wallet for the currency if missing.

**Models.** Models extend generated base classes from `database/schema.ts` (`WalletSchema`, etc.). That file is auto-generated from migrations — change columns via a migration, not by editing it. Models only add relations, hooks, and narrowed types.

**Imports** use Node subpath aliases from `package.json` (`#models/*`, `#services/*`, `#tests/*`, …) with `.js` extensions resolved to `.ts`.

**Demo-only behavior.** `DepositService` throws in production — deposits are a stand-in funding mechanism. Transfer receivers are identified by email (flagged as a TODO).

## Tests

Functional tests live in `tests/functional/`. Use the helpers in `tests/helpers/index.ts` (`createUser`, `createWallet`, `fundWallet`, `createUserWithBalance`) to set up state; `fundWallet` writes a completed deposit transaction plus a credit entry rather than touching a balance column.
